Deze procesreis gaat over klantdossiers waarbij de btw-administratie voor twee maanden is geboekt. Het dossier zit dan in een fase waarin de administratie al grotendeels is verwerkt, maar waarin nog een vervolgstap nodig kan zijn. Denk aan aanvullende informatie opvragen, een controle uitvoeren of het dossier voorbereiden op de volgende btw-periode. De procesreis start zodra de dealfase in HubSpot een van de volgende waarden krijgt: 2 maanden geboekt (info nodig) (BTW - Q, id 1162449030) 2 maanden geboekt (BTW - Q, id 1162621597) 2 maanden geboekt (controle) (BTW - Q, id 1162621598) Wanneer dit gebeurt, activeert HubSpot automatisch de workflow "BTW 2 maanden geboekt instellen". Deze workflow stuurt een signaal door naar de backend via POST /properties/btw/update_next_quarter_prev2m. De backend is in dit proces de laag achter HubSpot die de verdere verwerking uitvoert. Waar HubSpot registreert dat de klant in een bepaalde status staat, bepaalt de backend wat er vervolgens administratief moet gebeuren. In deze casus verwerkt de backend welke btw-periode of welk volgend kwartaal relevant is. Onder water loopt dat via /properties/btw/update_next_quarter_prev2m, verwerkt door GitLab worker "Update next quarter prev2m". Na deze verwerking kan de backend HubSpot bijwerken. In deze reconstructie zien we vooral dat dealgegevens in HubSpot worden bijgewerkt, waardoor de deal of het dossier een nieuwe status of eigenschap kan krijgen. Zodra HubSpot met die nieuwe gegevens is bijgewerkt, kunnen daar weer vervolgprocessen op starten. Andere workflows kunnen dan reageren op de nieuwe status of bijgewerkte dealgegevens. Zo ontstaat er een automatische procesketen: een wijziging in de dealstatus in HubSpot zet de workflow aan, de workflow geeft een signaal aan de backend, de backend verwerkt de juiste logica en HubSpot wordt daarna weer bijgewerkt voor de volgende stap in het btw-proces.
